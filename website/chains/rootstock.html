Note

THE OLDEST EVM FORK STILL RUNNING, AND ITS GAS SCHEDULE PROVES IT. Rootstock forked the EVM in 2018 and has since re-adopted mainnet features one RSKIP at a time, in an order mainnet never used. The result is a chain with Cancun-era opcodes (PUSH0, MCOPY, TLOAD/TSTORE) sitting on a Constantinople-era gas schedule: no EIP-1884 repricing, no EIP-2200 net metering, no EIP-2929 warm/cold accounting, no EIP-3529 refund reduction, and a 24,000-gas SELFDESTRUCT refund that mainnet deleted in 2021. It also has no EIP-2718 envelope at all — every transaction on this chain is a legacy transaction.

Silent divergences 17#

Wrong results with no revert, no error and no signal to the caller.

precompiles0x01 ECRECOVER
INPUT IS TRUNCATED, NOT PASSED. Since RSKIP516 (reed800, block 8,052,200) `Program.getInputLength` clamps the calldata handed to a precompile to that precompile's `getMaxInput()` — 128 bytes for ECRECOVER — and logs the truncation at debug level. Mainnet passes the whole input. For ECRECOVER the RESULT is unchanged, since mainnet already ignores everything past byte 128; it is recorded because the mechanism is shared with 0x09, where the result is NOT unchanged.
precompiles0x06 BN256_ADD
Input truncated to 128 bytes since RSKIP516. Same gas as mainnet (150), same result for well-formed input — but a caller that passes a longer buffer gets the first 128 bytes used instead of an error, and no signal that the rest was dropped.
precompiles0x07 BN256_MUL
input truncated to 96 bytes since RSKIP516; gas is Istanbul's 6,000.
precompiles0x09 BLAKE2F
THE TRUNCATION THAT CHANGES THE ANSWER. Mainnet's BLAKE2F REVERTS unless the input is exactly 213 bytes. Rootstock declares `getMaxInput() = 213` and `Program.getInputLength` silently clips anything longer, so a 300-byte call that reverts on mainnet SUCCEEDS here and returns a hash. Same address, same name, opposite outcome, no error either way.
precompiles0x0000000000000000000000000000000001000006 Bridge
THE TWO-WAY BTC PEG, AS A PRECOMPILE. Registers Bitcoin headers, validates SPV proofs, mints and burns RBTC, and holds the PowPeg federation's state. It is the largest precompile in this dataset by far and it moves native value: a peg-in credits RBTC to an address with no EVM-level transfer. It also cannot be recognised by code inspection — `eth_getCode` returns `0x`, exactly as for a nonexistent account.
eipsEIP-2718
NO TYPED-TRANSACTION ENVELOPE AT ALL. `org.ethereum.core.Transaction` decodes exactly nine RLP items — nonce, gasPrice, gasLimit, receiveAddress, value, data, v, r, s — with no type-byte branch anywhere in the class. There is no 0x01, no 0x02, no 0x03 and no 0x04 on this chain, and no way to add one without changing the transaction class. Confirmed live: 126 transactions across 30 consecutive blocks at head, every one of them type `0x0`.
eipsEIP-1559
NO BASE FEE, AND NOTHING IS BURNED. The header has no `baseFeePerGas`; it has `minimumGasPrice`, a miner-voted floor that moves by a bounded percentage per block, and `paidFees`, the total actually collected. Fees go to the miner and to REMASC, never to the zero address. `eth_getBlockByNumber` returns no `baseFeePerGas` key at all, so any transaction builder that reads it to compute `maxFeePerGas` gets `undefined`.
eipsEIP-3198
BASEFEE (0x48) EXISTS AND RETURNS SOMETHING ELSE. `doBASEFEE` pushes `program.getMinimumGasPrice()` — the miner-voted floor from the header, not an EIP-1559 base fee, because there is no EIP-1559 here. Solidity's `block.basefee` compiles to 0x48 and therefore reads a number with different dynamics, no burn semantics, and no relationship to congestion. It does not revert and gives no signal that it is answering a different question.
eipsEIP-4399
NO PREVRANDAO. Rootstock never merged, so 0x44 is still DIFFICULTY and `doDIFFICULTY` pushes the real merge-mining difficulty — a large, slowly moving, publicly known Bitcoin-derived number. `block.prevrandao` in Solidity compiles to 0x44, so any contract using it as an entropy source on Rootstock reads the mining difficulty, with no revert and no way for the caller to tell. The RPC compounds it: `mixHash` and `nonce` appear in the block JSON as all-zero even though NEITHER IS A CONSENSUS FIELD in this header — the RLP encoding in `BlockHeader.getEncoded` has no such items.
eipsEIP-2929
NO WARM/COLD ACCOUNTING ANYWHERE. There is no access list, no `AddressInAccessList`, no cold-slot surcharge; `GasCost.java` holds flat constants and the opcodes use them directly. SLOAD is 200 (mainnet: 2,100 cold / 100 warm), BALANCE 400 (2,600 / 100), EXTCODEHASH 400, EXTCODESIZE and EXTCODECOPY 700, CALL 700. First touch and hundredth cost the same. Gas estimates calibrated on mainnet are wrong in both directions, and a contract that budgets a fixed stipend for a repeated-SLOAD loop behaves differently here than anywhere else in this dataset except Taraxa.
eipsEIP-2200
NO NET GAS METERING. `doSSTORE` is the original three-branch schedule: null → non-zero costs 20,000, non-zero → zero costs 5,000 and refunds 15,000, everything else costs 5,000. There is no dirty-slot tracking, no `SSTORE_SENTRY` guard and no EIP-1283 either — so, unlike Taraxa, a 2,300-gas stipend cannot write storage here, because the CHEAPEST SSTORE is 5,000. The "transfer() cannot change state" premise survives on Rootstock, and it survives for the opposite reason from mainnet's.
eipsEIP-3529
SELFDESTRUCT STILL REFUNDS 24,000 GAS, AND THE REFUND CAP IS STILL gasUsed/2. `refundGas` accumulates `deleteAccounts.size() * GasCost.SUICIDE_REFUND` and then caps the total at `result.getGasUsed() / 2` — the pre-London quotient, not /5. `REFUND_SSTORE` is 15,000, not 4,800. Gas-token contracts (GST2, CHI) work on Rootstock, and the storage-clearing refund is more than three times mainnet's.
header_fieldsheader mixHash
NOT A CONSENSUS FIELD, BUT THE RPC PRINTS ONE. `BlockHeader.getEncoded` has no mixHash item; `eth_getBlockByNumber` nevertheless returns `mixHash: 0x00…00`. A tool that re-derives a block hash from the JSON, or that reads mixHash for randomness, gets a fabricated zero that no header ever committed to.
opcodes0x48 BASEFEE

opcodes0x44 DIFFICULTY

fee_modelfee model
THERE IS A MAXIMUM GAS PRICE, AND IT IS A CONSENSUS RULE. Since RSKIP252 (fingerroot500) a block containing a transaction whose gas price exceeds **100x the block's minimumGasPrice** is INVALID — `BlockTxsMaxGasPriceRule` rejects the whole block — and the mempool refuses anything over **80x** (`TxGasPriceCap.FOR_TRANSACTION`). No other chain in this dataset caps what a user may bid. The practical consequences: priority-fee auctions have a ceiling, a transaction cannot be rescued from a congested mempool by overpaying, and a wallet's "aggressive" fee preset built for mainnet can produce a transaction that no honest miner is able to include. The REMASC transaction is exempt by an explicit `instanceof` test.

Forks#

Precompiles 25#

PLACEMENT DISCIPLINE, AND THE ADDRESSES READ AS DECIMAL. Rootstock's seven custom precompiles sit at 0x01000006 through 0x01000017 — far above anything mainnet has allocated or is likely to, and far above the 0x64-0x69 range BSC, Core, Cronos, opBNB and Arbitrum are contending over. Note that the constants are written so they LOOK decimal (…01000016, …01000017) while being hex: the addresses between 0x01000011 and 0x01000016 are unused, and 0x01000012-0x01000015 are not what a reader skimming the list would guess.

Gotchas 8#

  • CANCUN OPCODES ON A CONSTANTINOPLE GAS SCHEDULE. PUSH0, MCOPY, TLOAD and TSTORE all work; SLOAD costs 200, BALANCE 400, SELFDESTRUCT refunds 24,000 and the refund cap is gasUsed/2. Nothing about the opcode set tells you the gas set, and every gas-based security argument written for mainnet has to be rechecked here.
  • THERE IS NO EIP-2718 ENVELOPE. Not "type 2 is rejected" — the transaction class decodes nine RLP items and has no type branch. Any library that signs an EIP-1559 transaction produces something Rootstock cannot parse.
  • A MAXIMUM GAS PRICE, ENFORCED AT BLOCK VALIDATION. 100x the block's minimumGasPrice, or the block is invalid. Wallet fee presets built for mainnet congestion can exceed it.
  • `block.prevrandao` RETURNS THE MINING DIFFICULTY, and `mixHash` in the block JSON is a fabricated zero that is not in the header at all.
  • PRECOMPILE INPUT IS TRUNCATED, NOT REJECTED. Since RSKIP516 a call to 0x01, 0x06, 0x07, 0x09, 0x01000016 or 0x01000017 with too much calldata has the excess silently dropped. On 0x09 that turns a mainnet revert into a success.
  • FOUR OPCODE BYTES ARE TOMBSTONED, THREE OF THEM BY A FORK THAT TURNED THEM OFF. 0xa8 DUPN, 0xa9 SWAPN and 0xaa TXINDEX were live until block 3,614,800; 0xfc HEADER was defined never to be valid. Old contracts containing them still exist.
  • THE BTC PEG IS A PRECOMPILE THAT MOVES NATIVE VALUE. `eth_getCode` on 0x…01000006 returns `0x`, indistinguishable from an empty account, and a peg-in credits RBTC with no EVM transfer to observe.
  • EVERY BLOCK ENDS WITH AN UNSIGNED TRANSACTION whose sender is the zero address encoded as a single zero byte — a pre-launch bug that is now consensus. An indexer that assumes every type-0x0 transaction has a recoverable signature will fail on one transaction per block, forever.

Full write-up#

Chain ID 30. Client rsksmart/rskj VETIVER-9.0.4 @ 731b9d8a, Java. Baseline fork petersburg. Live probes at block 9225919 (0x8cc6bf) on https://public-node.rsk.co.

web3_clientVersion returns RskJ/9.0.3/Linux/Java17/VETIVER-c19cf12 — mainnet runs 9.0.3 while 9.0.4 is the newest GitHub release, so the pin is one patch ahead of the network. Both are VETIVER and no consensus rule below differs between them.

A note on the tag ladder, because it costs an hour otherwise: RSKj versions are plant names — ORCHID → WASABI → PAPYRUS → IRIS → HOP → FINGERROOT → ARROWHEAD → LOVELL → REED → VETIVER — and sort -V over the tag list returns WASABI last.

1. The prediction was right, and about the wrong layer

CANDIDATES.md predicted "merge-mined, forked the EVM early enough that opcode-level drift is likely". Opcode drift is real (§4), but it is the second-biggest finding. The first is that Rootstock runs Cancun-era opcodes on a Constantinople-era gas schedule.

PUSH0 (RSKIP398), MCOPY (RSKIP445), TLOAD/TSTORE (RSKIP446) are all live. And:

mainnet today Rootstock
SLOAD 2,100 cold / 100 warm 200, flat
BALANCE 2,600 / 100 400, flat
EXTCODEHASH 2,600 / 100 400, flat
CALL, EXTCODESIZE, EXTCODECOPY 2,600 / 100 700, flat
SSTORE EIP-2200 net metering 20,000 / 5,000 / 5,000, no dirty tracking
storage-clear refund 4,800 15,000
SELFDESTRUCT refund 0 (removed at London) 24,000
refund cap gasUsed / 5 gasUsed / 2
MODEXP EIP-2565 (divisor 3) EIP-198 (divisor 20)

There is no access list anywhere in the tree: grep -ri 'warm\|cold\|accessList' over org/ethereum/vm/ returns nothing. EIP-2929, EIP-2200, EIP-3529 and EIP-6780 are all absent, and EIP-1884 was taken in half — SELFBALANCE arrived via RSKIP151, its repricings never did.

Two consequences worth stating plainly. Gas-token contracts (GST2, CHI) work on Rootstock. And the Taraxa finding inverts here: on Taraxa a 2,300-gas stipend can write storage because EIP-1283 shipped without its sentry; on Rootstock it cannot, because the cheapest SSTORE is 5,000. Same conclusion, opposite reason — and neither chain reaches it the way mainnet does.

2. There is no EIP-2718 envelope

org.ethereum.core.Transaction decodes nine RLP items and has no type branch. Not "type 2 is rejected" — absent from the transaction class. Confirmed live: 126 transactions across 30 consecutive blocks at head, every one type 0x0.

So Rootstock is the only row here whose envelope is narrower than mainnet's. It consumes no type byte and collides with nobody, which is the opposite end of the spectrum from Kaia's uint16 types and Celo's 0x7b.

3. The header is a different header, and the RPC hides it

BlockHeader.getEncoded produces:

parentHash, unclesHash, coinbase, stateRoot, txTrieRoot, receiptTrieRoot, logsBloom,
difficulty, number, gasLimit, gasUsed, timestamp, extraData,
paidFees, minimumGasPrice, uncleCount, [ummRoot], [rskPteEdges],
[btcMergedMiningHeader, btcMergedMiningMerkleProof, btcMergedMiningCoinbaseTx]

mixHash and nonce are not in it. eth_getBlockByNumber returns both anyway, as all-zero. Anything that re-derives a block hash from the JSON, or reads mixHash for randomness, is reading a value no header ever committed to.

And block.prevrandao is worse than zero: Rootstock never merged, so 0x44 is still DIFFICULTY and doDIFFICULTY pushes the real merge-mining difficulty (0x157d44759dd5edf5da5 at the probed block) — a large, slowly-moving, Bitcoin-derived number that any observer can predict. Solidity's block.prevrandao compiles to 0x44, with no revert and no signal.

4. Four tombstoned opcode bytes — three of them switched off by a fork

DUPN (0xa8), SWAPN (0xa9) and TXINDEX (0xaa) are in the enum, implemented in VM.java, and unreachable, because the dispatch inverts the usual gate:

case OpCodes.OP_DUPN:
    if (activations.isActive(RSKIP191)) {
        throw Program.ExceptionHelper.invalidOpCode(program);
    }
    doDUPN();

RSKIP191 activates at iris300, block 3,614,800. So these were live for four years and then turned off, and contracts deployed before that height that contain 0xa8 now halt on it. Mainnet has never allocated 0xa8–0xaa, so this is a delta against Rootstock's own history rather than against mainnet's — a direction the schema's vocabulary handles (tombstoned) but the dataset had not yet seen.

HEADER (0xfc) is the fourth, and it was born dead. The enum entry passes a script version of 256 with the comment "setting version==256 assures it's never considered valid (because scriptVersion range is 0..255)", and the dispatch case falls through to the raising default.

5. Precompile input is truncated, not rejected — and on 0x09 that changes the answer

Since RSKIP516 (reed800, block 8,052,200):

int maxInputFromContract = contract.getMaxInput() != NO_LIMIT_ON_MAX_INPUT ? … ;
int finalInputLength = maxInputFromContract == 0 ? 0 : Math.min(initialInputLength, maxInputFromContract);

with caps of 128 (ECRECOVER, BN128_ADD, SECP256K1_ADD), 96 (BN128_MUL, SECP256K1_MUL) and 213 (BLAKE2F). The excess is dropped and logged at debug level.

For ECRECOVER and the BN128 pair this changes nothing, because mainnet already ignores bytes past the expected length. For BLAKE2F it inverts the outcome: mainnet reverts unless the input is exactly 213 bytes, and Rootstock clips a 300-byte call to 213 and returns a hash. Same address, same name, opposite result, no error on either side.

This is a fifth flavour of same-address divergence to set beside the six the README lists — not a cap that makes the call revert (OP Stack) but a cap that makes it succeed.

6. There is a maximum gas price, and exceeding it invalidates the block

TxGasPriceCap is an enum with two members: FOR_BLOCK(100) and FOR_TRANSACTION(80). Since RSKIP252 a block containing any transaction whose gas price exceeds 100× that block's minimumGasPrice fails BlockTxsMaxGasPriceRule and is invalid; the mempool refuses anything over 80×.

No other chain in this dataset caps what a user may bid. Consequences: priority-fee auctions have a ceiling, a stuck transaction cannot be rescued by overpaying, and a wallet's "aggressive" preset calibrated for mainnet congestion can produce a transaction no honest miner is able to include. The REMASC transaction is exempt by an explicit instanceof test.

minimumGasPrice is also what BASEFEE returns (RSKIP412) — so block.basefee on Rootstock is a miner-voted floor with no burn semantics and no relationship to congestion.

7. Every block ends with an unsigned transaction whose sender is malformed on purpose

/**
 * The Remasc transaction is not signed so it has no sender.
 * Due to a bug in the implementation before mainnet release, this address has a
 * special encoding. Instead of the empty array, it is encoded as the array with
 * just one zero.
 */
public static final RskAddress REMASC_ADDRESS = new RskAddress(new byte[20]) { … };

It appears in eth_getBlockByNumber as an ordinary type: 0x0 transaction. An indexer that assumes every legacy transaction has a recoverable signature fails on one transaction per block, forever. In tx_authorization terms this is authorizes: protocol paired with precompile: none — the chain accepts a transaction its own contracts have no way to verify, because nothing signed it.

8. What is shipped and not on

rskPteEdges is a header field reserved for RSKIP144 parallel transaction execution, fully implemented in the client. It is bound to reed810, whose height in config/main.conf is -1. Confirmed live: rskPteEdges is null. RSKIP351 (header compression), RSKIP502 and RSKIP529 are parked at the same height.

Reading the activation state needs both config files and in that order: reference.conf maps a rule to a fork name, config/main.conf maps a fork name to a height, and main.conf may additionally pin one rule to a height of its own — which it currently does, for rskip536. Either file alone gives the wrong answer, which is why tools/verify.py's extractor reads both.

9. Address placement, and a hex trap

Seven custom precompiles at 0x01000006–0x01000017: Bridge (the BTC two-way peg), REMASC (rewards), HDWalletUtils (BIP-32 derivation), BlockHeaderContract, Environment (call-stack depth), and — since reed800 — secp256k1 point addition and scalar multiplication, which mainnet has never exposed despite signing with that curve.

Placement is safe: far above anything mainnet has allocated, and far above the 0x64–0x69 block that BSC, Core, Cronos, opBNB and Arbitrum are contending over. The trap is that the constants are written to look decimal — …01000016, …01000017 — while being hex, so 0x01000012–0x01000015 are unallocated and a reader skimming the list will mis-order them.

All seven return 0x from eth_getCode, indistinguishable from an empty account. The Bridge is the one that matters: it mints and burns RBTC, so a peg-in credits native value with no EVM-level transfer to observe.
