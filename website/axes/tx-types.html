Notes 2#

Type-byte allocation from both ends of the range#

EIP-2718 permits 0x00–0x7f. Mainnet allocates upward from 0x00; other chains allocate downward from the ceiling — zkSync 0x71, Arbitrum and Kaia both 0x78, Base 0x79, Celo 0x7b and 0x7c, the OP family 0x7d and 0x7e, Polygon 0x7f. There is no registry between the two frontiers. Current occupancy is computed from the data on the transaction types axis. Kaia's type numbers do not fit in a byte at all: they are uint16 (0x7801–0x7804), and Ethereum transactions are re-wrapped as 0x78 || ethType || rlp, so the RPC representation is standard while the consensus encoding is not.

Arbitrum · Base · OP Stack · Polygon · Celo · Kaia · zkSync

Transactions outside the EIP-2718 envelope#

Avalanche's atomic import and export transactions (UTXO, Avalanche codec) and all 43 of Tron's protobuf contract types carry no EIP-2718 type byte. Two chains with no shared ancestry required the same non_evm_transactions schema section. An indexer enumerating transactions through the EVM envelope does not see Avalanche's cross-chain value movement.

Avax C · Tron · Sei

Byte-range occupancy#

EIP-2718 allows 0x00–0x7f. Mainnet allocates upward from 0x00, other chains downward from the ceiling. Of the 128 legal bytes, 39 carry a live type, 1 is implemented in a client without anyone establishing reachability, and 3 have been deprecated — vacated, but not reusable, because old transactions still carry them. 85 are untouched.

Transactions outside EIP-2718#

Avalanche C-Chain#

Atomic transactions move value between the C-Chain and Avalanche's X/P chains. They are UTXO-based, serialised with Avalanche's own codec (not RLP), and registered in a separate codec namespace (plugin/evm/atomic/codec.go:33-34) — they live entirely OUTSIDE the EIP-2718 envelope while still being included in C-Chain blocks. No type byte can be assigned to them, which is why they cannot appear in tx_types.

Sei#

Two distinct populations with no EIP-2718 type byte. (1) Sei's own EVM-module Cosmos messages, which change EVM-visible state without ever being an Ethereum transaction. (2) A synthetic receipt kind emitted for ordinary Cosmos/CosmWasm transactions that produced EVM-shaped logs. The whole surrounding Cosmos-SDK message set (bank, staking, gov, IBC, wasm) is a third population, not enumerated here — it is standard Cosmos SDK and its EVM-visible effects are reachable through the 0x1001-0x100c precompiles.

Signed as EIP-712 typed data, not as a keccak of the RLP payload, so the signing domain includes the chain id structurally. Carries four fields with no mainnet analogue: gasPerPubdata (a second, independent price the sender commits to), factoryDeps (bytecodes published alongside the transaction — deployment does not go through initcode), customSignature (arbitrary bytes validated by the sender's own account contract, so signatures need not be secp256k1 at all) and paymasterParams (a third-party fee payer, protocol-level rather than an ERC-4337 bundler convention).

0x78EthereumTxTypeEnvelope1 chains
ChainDetail & provenance
Kaia➕
added silent divergence
NOT A TRANSACTION TYPE — a one-byte ESCAPE PREFIX. Ethereum typed transactions are stored and gossiped as `0x78 || <ethType> || rlp(body)`, giving internal type numbers 0x7801 AccessList, 0x7802 DynamicFee, 0x7803 Blob, 0x7804 SetCode. Kaia is a uint16 type space, not a byte one. The `eth_` RPC namespace strips the prefix on output and prepends it on input, so an Ethereum client never sees it — but anything reading block bodies, p2p traffic or Kaia's own `kaia_` namespace does. 0x78 also COLLIDES with Arbitrum's ArbitrumDepositTxType, the third collision in this dataset between chains with no shared code.

Celo➕
added spec: CIP-64 silent divergence
THE finding of this row. A 1559 transaction with one extra field, `FeeCurrency`, naming an ERC-20 that pays for gas. It sits ON TOP of the OP Stack envelope, one byte below Base's 0x79 and three below OP's 0x7e. It is not a curiosity: at the probed block it was the MAJORITY transaction type on the chain. A signer or indexer that handles OP Stack's 0x00-0x04 + 0x7e fails on most Celo traffic, and the sighash covers FeeCurrency, so the transaction cannot be re-signed as a 0x02.
