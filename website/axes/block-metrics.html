Each cell carries a pair: the code value the client or chain spec sets, then the observed value the network actually ran, shown only when it differs. Mainnet has no code value for its gas limit at all — go-ethereum bounds only how fast producers may move it — so the observed figure is the only answer that exists, and it decays. Gnosis shows the opposite case: a chain spec saying 10M against a network running 17M, both correct. The mutability tag says what it would take for the number to be different tomorrow, which is what decides whether an observation predicts anything. Gas / second is derived and never stored; it reads n/a where the gas limit is a sentinel rather than a capacity. A — means the question is not established for that chain. Every column sorts. Click a heading to rank by that column — biggest first, then smallest, then back to the reading order. The sort follows the number, not the presentation: the observed value where there is one, because that is what the network ran; the code value otherwise. The mutability tag is ignored, since config and unbounded say what it would take to change the figure rather than how big it is. Rows with no comparable value park at the bottom in both directions — a chain that does not state a limit has not thereby got a small one, and a sentinel is not a capacity.

Limits that fit no column 2#

ChainLimitWhat it does
zkSyncpubdata per batch

The real bound on an EraVM batch, and it is denominated in BYTES of state diff published to L1 rather than in gas. A batch seals when pubdata fills, when the prover's circuits fill, or on a timer — none of which the header's 2^50 gasLimit describes. The circuit half is recorded on the proofs axis as prover_constraints.

Sonicgas power per second

THE LIMIT THAT ACTUALLY BINDS. Sonic allocates gas as a per-second power budget shared among validators by stake, so a validator's capacity refills with time rather than resetting at a block boundary. The 5,000,000,000 header gasLimit is a technical ceiling nothing reaches, which is why the derived throughput column on this row should not be believed.
