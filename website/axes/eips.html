Notes 2#

Fork names and EIP sets diverge in both directions#

BSC activated Prague seven weeks before mainnet and Osaka five months after. Avalanche has P256VERIFY (an Osaka feature) without BLS12-381 (a Prague feature). OP Stack's precompile switch tests IsOptimismJovian before IsOsaka, so activating Osaka does not restore mainnet semantics. Fork names are recorded as claims; the eips: map is the measurement.

BNB · Avax C · OP Stack

Four fork-activation mechanisms#

OP Stack enforces timestamp equality at startup. Avalanche assigns timestamps. Arbitrum gates on ArbOS version and ignores timestamps. Polygon uses block numbers. Reading a fork timestamp is not a general method across this dataset.

OP Stack · Avax C · Arbitrum · Polygon

Baseline fork claimed#

Grouped by the mainnet fork each chain claims equivalence to, most recent fork first. Within a group, the chain with the most recent dated activation comes first; chains whose forks are gated on something other than a timestamp — an ArbOS version, a block number — have no date and follow.

Sei⚠️
modified silent divergence
Two independent divergences. (a) The base fee is NOT BURNED — the full baseFee + tip is credited to the fee-collector address as the coinbase reward, with an explicit comment saying so. Every supply model that assumes 1559 burn is wrong on Sei. (b) The base fee update rule is not 1559's: it moves toward a governance TargetGasUsedPerBlock (default 250k gas) by at most +1.89% / -0.39% per block, scaled by how far the block was from target, and is then clamped between governance MinimumFeePerGas and MaximumFeePerGas. Monad⚠️
modified silent divergence
Replaced wholesale by the Monad TFM. Differences from EIP-1559, all of them consensus-relevant: the target is 80% of the gas limit, not 50%; the update is an adaptive exponential whose step size is damped by an EWMA `trend` and variance `moment` carried in the CONSENSUS header (MonadConsensusBlockHeaderV2), not derivable from the Ethereum header; the base fee is clamped to [100 gwei, 1e17 wei]; and the input is the SUM OF TRANSACTION GAS LIMITS in the parent block, not gas consumed. Kaia⚠️
modified silent divergence
Kaia's envelope is EIP-2718-SHAPED BUT NOT EIP-2718. A typed transaction is `rlp(txType) || rlp(body)` where txType is a uint16, and Ethereum's own typed transactions are re-wrapped as `0x78 || <ethType> || rlp(body)` when stored or gossiped. The `eth_` namespace strips the 0x78 on the way out and re-adds it on the way in, so eth_sendRawTransaction and eth_getRawTransactionByHash look standard while the consensus encoding is not. THE finding of this row, and it is bigger than EIP-3529. From MONAD_ONE onwards compute_gas_refund returns 0 UNCONDITIONALLY — not just the SSTORE clear refund, but the Yellow Paper's g* itself. execute_final then computes `gas_used = tx.gas_limit - gas_refund`, so gas_used is IDENTICALLY the transaction's gas limit.
