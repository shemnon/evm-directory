Notes 7#

A transaction ordered before it is executed has seven different fates#

Mainnet checks nonce, balance and gas price before a transaction is ordered, so "ordered but invalid" is not a state it can reach. Every chain that separates ordering from execution has to invent an answer, and ten rows here have invented seven. Erasure, by four unrelated mechanisms: Conflux defines a third receipt outcome, TransactionStatus::Skipped, then deletes the transaction from the block, the transaction index and eth_getTransactionReceipt alike; IOTA EVM rejects at the ISC request layer before the EVM is entered, so there is no receipt to write; Artela emits its indexing event from the last ante decorator, so an ante failure leaves the CometBFT index with no entry while the transaction sits provably in the block; Rollkit's builder logs a warn! and does not append. In all four, eth_getTransactionReceipt returns null forever and the transaction is indistinguishable from one never submitted. Taraxa is the counter-pole: no skip path at all — included, charged the full gas limit, status: 0. Autonomys escalates: the offending transaction poisons its whole Bundle, every valid co-passenger is dropped, and the operator is automatically slashed under SlashedReason::InvalidBundle. Berachain rejects the block: the EVM sits behind the Engine API, whose newPayload verdict has no per-transaction skip, so ProcessProposal returns REJECT and the client sees nothing at all. RISE and MegaETH make the state unreachable, by opposite routes — RISE admits synchronously and publishes only after executing, MegaETH creates the state inside the builder and resolves it before publication. Monad charges it, inside execution. Hedera bills it without ever executing it, and the bill may land on the node: fees are charged before the handler is reached, and the split is by who was negligent rather than by what failed — a due-diligence failure (expiry re-checked against the consensus clock, a bad payer signature) debits the submitting node's account and the payer nothing, while a duplicate or an unaffordable service fee debits the payer and never calls the handler. It is the only row where the node pays for the sender's invalid transaction. A record always exists, because Hedera cannot drop something that reached consensus — but for a wrapped Ethereum transaction the Ethereum hash is written only inside the handler, so the eth_* view is null forever anyway. There is no portable answer to "was my transaction included", and a null receipt means "still pending" on some of these chains, "gone forever" on others, and "gone, and you were charged" on one.

Same consensus engine, opposite failure mode — the Engine API is the discriminator#

Berachain and Artela both run CometBFT and both must answer what happens to a transaction that is in a proposal but invalid when it executes. They answer oppositely, and the discriminator is not the consensus engine but where the EVM runs. Artela's EVM is in-process behind an ante-handler chain, so failure is per-transaction: the transaction is erased, provably in the CometBFT block yet with no index entry and a permanently null receipt. Berachain's EVM is a separate process reached over the Engine API, whose engine_newPayload verdict covers the whole payload with no per-transaction skip, so failure is per-block — ProcessProposal returns PROCESS_PROPOSAL_STATUS_REJECT, CometBFT re-proposes the height, and an RPC client observes nothing at all. Berachain goes further: CometBFT never orders EVM transactions in the first place, since prepareProposal ignores req.Txs and returns exactly two entries, the SSZ beacon block and its blob sidecars. Any generalisation of the form "Cosmos/CometBFT chains behave like X" is wrong in one of the two directions; the question to ask is whether the EVM is inside the ABCI application or behind the Engine API.

Bera · Artela

The finalized block tag means something different on every chain that has one#

Any chain speaking the Engine API inherits Ethereum's safe and finalized block tags whether or not it has anything to put behind them, and four rows here fill them with four incompatible meanings. Autonomys is honest and extreme: finalized sits 14,994 blocks — roughly twenty-four hours — behind latest, the optimistic execution challenge window plus the consensus chain's confirmation depth, and safe returns the identical block, so there is no intermediate tier. Rollkit fills them by arithmetic — safe = head-2, finalized = head-3 — under a source comment calling it "a temporary mock value until proper DA-based finalization is wired up"; the DA-driven update that would make them meaningful is overwritten by the next block, ten times a second, leaving finalized 0.7 s behind head on a chain whose data layer settles every 6 s. IOTA EVM maps every negative tag to latest, so finalized, safe and pending return byte-identical head blocks while the RPC serves a state its own source documents as "can be ahead of ConfirmedState". RISE and MegaETH publish full receipts for blocks that do not exist yet. A bridge that waits for finalized waits a day on one chain and gets a strictly weaker guarantee than latest plus a fixed wall-clock delay on another, with nothing in the RPC response to distinguish the cases.

Three sentinels for "this block does not exist yet", and one reaches unmodified clients#

MegaETH and RISE both publish a transaction's result before its enclosing block is sealed, and both must name a block hash they do not yet have. They chose different sentinels and, more importantly, different blast radii. MegaETH confines it to an opt-in WebSocket stream — a mini-block receipt carries blockHash: 0xffff…ff, while plain HTTP returns null — so a standard client is safe by default. RISE returns the preconfirmed receipt over ordinary eth_getTransactionReceipt with blockHash: 0x0000…0000, and additionally replaces rather than extends eth_subscribe(["logs"]) so that channel silently carries shred logs with blockHash: null. On RISE an integrator who changed nothing is already consuming preconfirmations, storing a valid-looking zero bytes32 that will never match a real block. Both chains also contradict themselves within one payload: the streamed receipt and the streamed transaction disagree about the same missing hash. RISE's shreds are unsigned, so a contradicted preconfirmation cannot be proven; MegaETH's mini-blocks are signed. A defence written for one chain fails on the other, and RISE uses two sentinels itself.

RISE · MegaETH

Chains that fix inclusion before balances are known confiscate rather than reject#

On mainnet a transaction that cannot cover gas_limit * gas_price is simply not includable — the check runs before ordering. Where proposers fix an order without knowing the balance it will execute against, the state transition has to do something, and two chains with no shared ancestry independently chose to take whatever the sender has. Taraxa computes available_funds_gas = balance / gas_price and subtracts all but sub-gas-price dust; Conflux takes min(gas_cost, balance). Both bump the nonce, both emit a status: 0 receipt, and both report a gasUsed that is a function of the sender's balance rather than of work performed — so the receipt field that every explorer and cost model reads as "work done" is, in this case, a measure of how poor the sender was. Two independent arrivals at the same design make it a property of the ordering model rather than a quirk of either client.

Taraxa · Conflux

What counts as "the same transaction" is not the same question on every chain#

Where many proposers build blocks at once, the same transaction landing in more than one block is the normal case rather than an edge case, and the dataset holds three mechanisms operating at three different layers. Taraxa deduplicates at period assembly, before the ordered block set becomes a transaction list: the duplicate never executes, but the DAG block carrying it stays in the period data, so it remains visible in the DAG and is absent only from the executed list. Conflux executes it, gets OldNonce, marks it Skipped, and then erases every trace — from the block body, the transaction index and eth_getTransactionReceipt alike, so the duplicate is indistinguishable from a transaction never submitted. Taraxa credits fees strictly to the first includer and, before its Aspen fork, gave a DAG block no reward at all unless it contributed a unique transaction: nobody is charged and nobody is slashed, and the only cost of losing the race is forgone revenue. Where deduplication happens — before ordering, or after execution — determines what a client can observe, and the two are not interchangeable. Hedera makes the identity model itself the divergence. A transaction there is keyed by TransactionID = (payer account, valid-start timestamp) — nothing about the contents enters the key, so two byte-identical submissions with different valid-starts are different transactions and two unrelated bodies sharing a payer and timestamp are the same one — and uniqueness holds only inside a 180-second window, after which an ID may be reused. Duplicates are the designed-for case, because the SDKs submit to several nodes for reliability. Hedera then does what no other row does: it charges for them. A duplicate first seen from another node debits the payer the node and network fees with the service fee waived and never executes; a duplicate from the same node debits that node instead; and the node that lost the race is paid the node fee, so losing is revenue. None of it is visible to Ethereum tooling — the Ethereum hash is recorded only inside the handler a duplicate never reaches — so an operator sees an HBAR debit with no eth_* object to attribute it to. Taraxa charges nobody, Conflux erases everything, Hedera bills silently. Sonic dedupes in four layers and the layer that applies depends on an on-chain toggle: an emitter-side stake lottery, a seenHashes pass over the confirmed event set during block derivation, and a nonce precheck at execution — but its SingleProposerBlockFormation mode bypasses the hash dedup entirely, leaving only trial-execution at the proposer. The duplicate vanishes from eth_* exactly as on Conflux, yet dag_getEventPayload still lists it one level down, exactly as on Taraxa; the whole fee is credited to the first ordered event's creator and the losing emitter is unrewarded but not slashed. Monad is the strong negative: no deduplication anywhere, because a block containing a duplicate is rejected. Two consensus checks do it — a within-block nonce_usages set, and a cross-block coherency check that reconstructs expected nonces from the triedb at N-3 plus the NonceUsageMap of every uncommitted ancestor, which is what deferred execution forces. Autonomys deduplicates by byte equality across the concatenation of every valid bundle, after per-bundle validity classification — so an ordinary duplicate is explicitly not one of InvalidBundleType's six variants and its author is never slashed. That is the inversion worth noting: on the one chain where a stale nonce inside a bundle is a slashable protocol violation, submitting the same transaction twice is not.

Taraxa · Conflux · Hedera · Sonic · Monad · Auto EVM

A failed transaction may spend your nonce and show you nothing#

On mainnet the question cannot arise: an invalid transaction is never included, so the nonce is always preserved and the sender resubmits freely. Where ordering is separated from execution, the nonce may be spent by a transaction that did no work — and on three rows it is spent by a transaction the RPC will not admit exists. cosmos-evm is the ancestor case, and it is deliberate. MonoDecorator commits the fee deduction and IncrementNonce, and the Cosmos SDK commits ante writes before running the message; then TxSucessOrExpectedFailure — res.Code == 0 || TxExceedBlockGasLimit(res) — drops everything else out of EthMsgsFromCometBlock. So a post-ante error (failed to commit stateDB, refund gas-overflow, any recovered panic) takes the fee, burns the nonce, and erases the transaction from the block, the hash lookup and the receipt store alike. The framework's own test TestEthMsgsFromCometBlockSkipStateDBCommitFailure pins it with a literal {Code: 4, Log: "failed to commit stateDB"}, and the one escape hatch is a substring match on the block-gas-limit error string, whitelisted back into visibility with the in-source reason that a fee-taken transaction must stay visible — applied to exactly one of the several ways a fee can be taken. artela is the dangerous instance: same shape, but its PREVRANDAO nil-dereference makes the state reachable from ordinary bytecode rather than from an internal error, and its queryCosmosTxIndexer is stricter still. A sender sees no receipt, concludes nothing happened, resubmits at the same nonce, and is permanently behind a gap no RPC call will reveal. injective inherits only half of it — verified against its own tree rather than assumed: it replaces the framework ante chain with CheckEthSenderNonce and applies no result filter in EthMsgsFromTendermintBlock, so the nonce is burned and the receipt is lost, but the transaction still appears in the block and the gap is observable. sei is the deliberate counter-example: the nonce bump and the stub receipt are gated on the same condition, so a spent nonce always has a receipt and a missing receipt always means a preserved nonce. Elsewhere the axis splits without danger: sonic and monad reached the same fee-only balance check from unrelated directions and burn the nonce with a status: 0 receipt; taraxa sets rather than increments, so one transaction can burn an unbounded range of nonces; conflux and iota-evm each preserve on one path and burn on another; and hedera preserves the nonce in both its failure modes while taking HBAR anyway. The portable lesson is that "no receipt" does not mean "nothing happened", and the sender cannot tell the two apart from the Ethereum RPC alone.
