delegate is not a migration. EIP-7702 lets an address run code that checks a post-quantum signature, but the secp256k1 key that signed the delegation keeps full authority, can sign a new delegation, and still satisfies every ecrecover check. Read it together with classical_key: only a row that can retire the original key has a complete answer for an existing account. scheme-field on a row with a native, non-Ethereum format (Hedera, the Cosmos family) is that format's answer; the EVM envelope on the same chain stays fixed, and the chain page says so. A — means the question is not established for that chain. Consensus and p2p signatures are out of scope here.

Notes 1#

Most chains can attach a post-quantum key to an address; only three can switch off the old one#

A post-quantum migration for an existing account has two halves: binding a new key to the address, and stopping the old key from signing for it. EIP-7702 covers the first half. On every row where it is live, the delegating key keeps full authority: the EIP-3607 sender check exempts a delegation, the key can sign a replacement delegation, and ecrecover ignores account state, so permit-style checks keep accepting it. Ethereum has two proposals for the second half. EIP-8151 would make ecrecover respect account code; it is Considered for Inclusion in Hegotá. EIP-7851 would add an ECDSA-disabled delegation prefix; it was Declined. Base's EIP-8130, gated off on mainnet, and a Monad draft both separate the address from the key. Only Kaia, Hedera and Tron let an account retire the original key today, each through a registration transaction the protocol already has. None of the three can yet register a post-quantum key. Tempo also binds new keys to an address, through its keychain, but the root key cannot be revoked. No row authorizes a transaction with a post-quantum signature on mainnet. zkSync Era and the zk-stack come closest: account code decides what a valid signature is. There, the limit is the sequencer's node-configured validation gas cap, since no post-quantum precompile exists. Arc (SLH-DSA) and Taraxa (Falcon-512) can verify a post-quantum signature in a contract, but not authorize a transaction with one.
