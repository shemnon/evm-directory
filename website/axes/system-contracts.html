Bytecode that changes with no transaction#

mutable bytecode

BNB Smart Chain — BSC REWRITES system-contract bytecode at fork boundaries via statedb.SetCode. Twenty per-fork bytecode directories exist (bruno, euler, gibbs, moran, planck, plato, luban, kepler, feynman, haber_fix, bohr, pascal, lorentz, maxwell, fermi, pasteur, ...). Unique in this dataset: on every other chain, code at an address changes only by transaction. Here the client swaps it, so the same address can have completely different behaviour across a fork with no on-chain transaction to observe.

122 bytes. The disassembly is even smaller than CoreWriter: it REVERTS if calldatasize is nonzero, so it accepts only plain value transfers, and on an empty call it emits LOG2 with topic 0x88a5966d..5874 carrying msg.value as data and msg.sender as an indexed topic. Same shape as CoreWriter and the same hazard: sending native HYPE here moves it to HyperCore by log interpretation, with no EVM-level confirmation that the credit occurred, and it is a one-way door for anything sent by mistake. Its account also reports a nonce of 1015323, which no ordinary contract would accumulate — see system_transactions.

0x3333333333333333333333333333333333333333CoreWriter1 chains
ChainDetail & provenance
Hyperliquid➕
added silent divergence
544 bytes of bytecode. Disassembly of the deployed code shows the WHOLE contract: one selector 0x17938e13, an empty 400-iteration loop (PUSH2 0x0190, pure gas burn), then LOG2 of one event, then return. The selector is keccak "sendRawAction(bytes)" and the log topic 0x8c7f585f..12e3 is keccak "RawAction(address,bytes)" — both recomputed locally and matched exactly against the constants embedded in the bytecode and against live logs on chain. Measured cost agrees with the disassembly: eth_estimateGas gives 47042 against a 21000 baseline, and 400 loop iterations plus a two-topic log is about that. severity: high. THERE IS NO SUCCESS SIGNAL. sendRawAction has no return value and cannot revert on a rejected action, because the EVM side only emits a log — HyperCore interprets it afterwards, asynchronously, outside the EVM. A contract that places an order, cancels one, or moves funds through CoreWriter receives a successful call whether HyperCore accepts or rejects the action. Every EVM-level guarantee stops at the log boundary, and no amount of checking the return value helps because there is none.
